## Objective
Add a `NexusTests` target to `project.yml` and cover the deterministic functions first —
the tracker merge key, the compressor's format choice, palette search scoring, config
decode and defaults, and `nexus://` URL parsing — so a refactor cannot change them
silently.

## Context
- `project.yml:35-36` — `targets:` declares exactly one target, `Nexus` (`type: application`).
  There is no test target anywhere in the project.
- `project.yml:10-12` and `project.yml:13-30` — `configs:` and the base `settings:` block
  (`SWIFT_VERSION: "5.9"`, `SWIFT_STRICT_CONCURRENCY: "minimal"`, `MACOSX_DEPLOYMENT_TARGET: "13.0"`).
  A test target inherits these, so it must build in Swift 5.9 mode under the CI Xcode.
- `project.yml:31-34` — `packages:` declares GRDB 6.29.0. A test target that touches
  repositories would need the same dependency; pure functions do not, which is part of
  why they are the first coverage.
- `project.yml:39-42` — the `Nexus` target's `sources: - path: Nexus`. Test sources must
  live outside `Nexus/` or this glob pulls them into the app binary.
- `.gitignore:10` — `Nexus.xcodeproj/` is gitignored and regenerated by
  `xcodegen generate` (`scripts/build-mac.sh:33-34`), so the target definition must live
  in `project.yml`; an edit made in the project file would be lost on the next build.
- `Nexus/Features/Tracker/TrackerService.swift:141-145` — `private static func
  isSameActivity(_:_:)`: the merge key. Two records are "the same activity" when `app`
  matches and `context?.file` matches; it is what decides `extendLastRecord` vs `insert`
  at `:133-138`.
- `Nexus/Features/Uploader/ImageCompressor.swift:90-124` — `private static func
  autoStrategy(...)`, the format choice: GIF passes through (`:95`), alpha prefers WebP
  when it is smaller and falls back to PNG (`:97-107`), no-alpha takes the smaller of
  JPEG and WebP (`:108-123`). It reads `webpEncodeSupported` (`:99`, `:110`, `:114`), an
  environment-dependent flag, so a deterministic test must pin or inject it.
- `Nexus/Features/Uploader/ImageCompressor.swift:42-67` — `static func
  compress(_:quality:format:)` is the public entry point. Testing through it avoids the
  `private` problem but needs real image bytes and a working ImageIO/WebP environment.
- `Nexus/Features/Palette/PaletteSearch.swift:6-29` — `@MainActor enum PaletteSearch`
  with `static func score(_:query:)`: empty query returns the input unchanged (`:12`),
  otherwise commands are scored, filtered to `> 0`, and sorted by score then insertion
  order (`:23-28`). `total` (`:31-39`) and `field` (`:41-62`) are private but reachable
  through `score`.
- `Nexus/Core/CommandRegistry.swift:11-19` — `struct Command`, whose `title`, `when`,
  `subtitle` and `run` are all `@MainActor` closures. Building fixtures for
  `PaletteSearch.score` therefore requires a `@MainActor` test method.
- `Nexus/Core/ConfigSchema.swift:10-170` — `AppConfig` and the per-section structs, each
  with a tolerant `init(from:)` that falls back per missing field (`:19`, `:40`, `:78`,
  `:94`, `:108`, `:123`, `:141`, `:154`, `:165`). All internal, so directly testable.
- `Nexus/Resources/default-config.json` — the embedded defaults that `ConfigSchema.swift`
  mirrors value-for-value (per `.ea/report/features-inventory.md`'s config table). A decode
  test should assert that decoding this file equals the Swift defaults.
- `Nexus/Core/URLScheme.swift:45-72` — `func dispatch(url:)` on `@MainActor final class
  URLSchemeHandler`: scheme check (`:46-49`), host check (`:50-53`), leading-slash strip
  (`:55`), empty-id guard (`:56-59`), registry lookup (`:60-63`), the dangerous branch
  (`:64-68`), and `await cmd.run()` (`:69-71`). Parsing is interleaved with dispatch and
  with `CommandRegistry.shared`, which is a process-wide singleton.
- `Nexus/App/AppEnvironment.swift:22-46` — `AppEnvironment.init` opens the real database
  and `fatalError`s on failure (`:26-31`). A hosted test bundle would run this, which is
  why the pure-logic tests must not need it.
- `.ea/spec/migration.md:136-149` — "## Tests required before cutover" names eight tests.
  Four (the decode and round-trip rows) need no UI; the other four (AX permission
  survival, hotkey conflict, tray drop, `nexus://` from Shortcuts) need a real app session.
- `.ea/report/features-inventory.md:1152` — records those eight tests as `Missing`, with
  the basis "no test target and no `*Tests*` directory".
- `.ea/spec/pitfalls.md:117-124` (§1.3) — the CI Xcode is the gating toolchain. `import
  Testing` (swift-testing) requires Xcode 16+, so the target must use XCTest.
- `.ea/report/gap-analysis.md` §2 V-09 — the finding; its "Smallest automated check"
  paragraph is the shape of this issue.

## Tasks

- [ ] Add the scheme wiring needed for `xcodebuild test -scheme Nexus` to run the target on a clean checkout — `project.yml` declares no `schemes:` today and XcodeGen 2.46 emits no shared scheme
- [ ] Use XCTest rather than swift-testing: `SWIFT_VERSION` is `5.9` (`project.yml:15`) and the CI Xcode is 15, where `import Testing` is unavailable
- [ ] Cover the tracker merge key (`TrackerService.isSameActivity`, `:142-145`): same app + same file merges; a different app, or a different file, does not
- [ ] Cover the compressor's format choice (`ImageCompressor.autoStrategy`, `:90-124`): alpha prefers WebP when smaller and otherwise PNG; no-alpha takes the smaller of JPEG and WebP; GIF passes through — with `webpEncodeSupported` pinned so the result is deterministic
- [ ] Cover palette search scoring (`PaletteSearch.score`, `:10-29`): an empty query returns the input unchanged; title outranks group outranks keywords outranks subtitle; equal scores keep insertion order
- [ ] Cover config decode and defaults (`ConfigSchema.swift`): decoding `Nexus/Resources/default-config.json` yields the Swift defaults, and a partial object falls back per missing field instead of throwing
- [ ] Cover `nexus://` URL parsing (`URLScheme.swift:45-63`): valid `nexus://command/<id>`, a non-`nexus` scheme, a wrong host, an empty id, and an unknown id
- [ ] Widen whatever access is required to reach the `private` members under test, or test through the public entry point — and record which choice was made
- [ ] Keep the tests free of AppKit, GRDB and UI where the function allows it, so they run without launching the app

## Boundaries
- Always: define the target in `project.yml` — `Nexus.xcodeproj/` is gitignored (`.gitignore:10`) and regenerated by `xcodegen generate`, so a change made in the project file is lost
- Always: use XCTest — `SWIFT_VERSION: "5.9"` (`project.yml:15`) and the CI Xcode 15 rule out `import Testing`
- Always: keep test sources outside `Nexus/`, so the app target's `path: Nexus` glob (`project.yml:39-42`) does not pull test code into the shipped binary
- Never: let these tests depend on the app's bootstrap. A hosted bundle runs `AppDelegate.applicationDidFinishLaunching` and `AppEnvironment.init`, which opens the real database (`AppEnvironment.swift:26-31`)
- Never: weaken `ConfigSchema`'s tolerant decoding to make a test pass — the per-field fallback is the behaviour under test (`ConfigSchema.swift:19`, `:40`, `:78`, …)
- Never: add a test that only asserts a function does not throw; each test must pin the branch it covers
- Ask: how to reach the `private static` members under test. `TrackerService.isSameActivity` (`:142`) and `ImageCompressor.autoStrategy` (`:90`) are `private`, and `@testable import` does not expose `private` — the choice is to widen them to `internal` (a small, honest visibility change) or to test through `compress(_:quality:format:)` and the tracker's public merge path (no visibility change, heavier fixture). Record the decision
- Ask: whether `PaletteSearch`'s `@MainActor` isolation (`PaletteSearch.swift:6`) should be lifted so scoring can be tested without a main-actor test method, or whether the test should simply be `@MainActor`. The second is less invasive; the first would also let the function run off the main actor
- Ask: whether to extract `nexus://` parsing from `URLSchemeHandler.dispatch(url:)` (`URLScheme.swift:45-63`) into a pure function returning a parse result. Parsing is currently interleaved with a `CommandRegistry.shared` lookup (`:60`), so testing it either touches the shared singleton or requires that extraction — cleaner design, but a production change riding on a test-target issue
- Ask: whether `NexusTests` should be a hosted bundle (`TEST_HOST` = `Nexus`, XcodeGen's default when a test target depends on an app target) or unhosted. Hosted is the standard recipe but launches the app; unhosted requires the logic to live somewhere the bundle can link. This decides whether the "no database side effects" acceptance criterion is reachable as written
