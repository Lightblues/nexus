# 2026-10-31 — Making the data usable

Status: settled; implemented the same night (SADR-020).

## What the review found (2026-10-30)

The user asked how the tracker works, whether its data is enough, how intake uses it, which old layers can go, and
whether a CLI is needed. Findings on the server's data (owner, 2026-04-28 to 10-30):

- 102,812 tracker rows, median 5 s. Polling the front window every few seconds and merging same-window runs is
  enough for time by app, project and site; it was never summarized anywhere.
- `loginwindow` had 318 h: sleep and the lock screen were extended into the last record. Other apps had a few
  multi-hour rows from the same bug (Chrome: 5 rows, 24 h).
- No tracker rows from 2026-07-21 to 10-27 (pomodoros continued): the tracker was waiting for Accessibility after
  the re-signed builds, silently.
- VS Code projects were wrong: "Lightweight" (165 h) is the window's profile name, the last title segment.
- No categories; intake copied every raw row into `raw` and nothing read them.
- Settings had two homes (`config.json` watched and Mackup-managed, and synced records).

## Decisions

- Keep the standard `~/Library` layout (no `~/.nexus`); delete `~/.ea/nexus*` leftovers by hand.
- Settings live in `nexus.db`; `config.json` is imported once and renamed. Sync carries them between Macs; the
  CLI changes them through the server.
- The server cleans and categorizes, and stores one summary per day. Old rows are corrected at read time, not
  rewritten.
- intake takes day summaries, one way, as with iris. The raw rows it already has stay frozen.
- The CLI reads the server, not a Mac: one server and one key, no hosts. Ops on a Mac wait for the relay.
- The web app is read-only, as decided 2026-10-30; it logs in with a key and keeps a read-only session.

## Tracker fixes (app, v1.3.2)

Lock-screen bundle ids are skipped like idle; a record extends only when the gap since its end is under three polls
(15 s at least); a notification after 10 minutes if Accessibility is still missing; editor project from the
`file — project` title segment; `enrichApps` is the only gate, with a wider default (VS Code, Cursor, Chrome,
Safari, Arc).

## First numbers

With the cleaning, a typical tracked weekday is 6–10 h active, 60–80 % coding. Six months of summaries rebuild in
about two seconds.
