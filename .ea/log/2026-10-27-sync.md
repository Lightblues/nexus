# 2026-10-27: nexus sync

Participants: Eason + Cursor agent (orchestrating from the intake repo). Status: server and package done; app wiring in progress on the Mac (nexus-018).

## Why

nexus data (pomodoro sessions, tracker records, settings) lived in one Mac's SQLite. Two Macs could not share it, and intake could not read it. intake's product-boundaries discussion (intake `.ea/log/2026-10-23-product-boundaries.md`) settled that each app owns its sync service and exports through `/export/changes`.

## What changed

| Area | Result | Where |
|---|---|---|
| Server | `services/server` (TS, Postgres `nexus` on cpu, `127.0.0.1:33033`, `https://nexus.easonsi.site`): generic records, push/pull with last write wins, export without settings | SADR-016 (`log/decisions.md`), nexus-016, `.ea/docs/sync.md` |
| Client | `Packages/NexusSync` (GRDB 7 only): outbox triggers, push/pull, settings first contact (server wins), tracker `uid`; tested on Linux in `swift:6.1-noble` and end to end against the real server | SADR-017, nexus-017 |
| App | GRDB 7, `NexusSync` as a local package, CI on `macos-15` | nexus-017 |
| Settings | Every setting syncs with one switch (personal use), except the sync connection itself | nexus-018 |

## Relation to intake

- sonar's `export_changes app=nexus` (`NEXUS_URL`, `NEXUS_READ_KEY`) feeds intake's `sync-nexus` job, which writes `raw` rows with `source=nexus` (pomodoro_session, pomodoro_project, pomodoro_tag, tracker_record). Settings are not exported (they hold the uploader's GitHub token).
- intake does not build a nexus view; its agent answers from `raw`. If charts are wanted later, a small page goes on the nexus server.

## Rollout (evening)

- nexus-018 released as v1.3.0 from tx-mbp-m5pro (CI on `macos-15` built GRDB 7 + NexusSync first try); tx-mbp-m1pro moved from Electron 0.6.0 to the cask. Only m5pro develops; other Macs install releases through Homebrew.
- Incident: m1pro's Settings window was opened before its first pull, so its draft held defaults. `isDirty` compared the draft with the pulled config, kept the stale draft, and a Save wrote it whole; the next sync pushed 5 default settings (GitHub token, owner, repo, `tracker.recordTitle`, palette hotkey) as fresh edits, and m5pro pulled them. Restored from mackup `1ad7e4a` by clearing those keys from m5pro's `sync_settings` so they pushed as newer. Fixed in v1.3.1 (`c3724a5`: the draft rebases on external changes and Save writes only edited keys; `9eb8a39`: a changed hotkey re-registers with the new value). Both Macs on v1.3.1, converged.
